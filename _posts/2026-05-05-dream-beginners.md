# Dreamhack Dream Beginners 내용 정리


## '**해킹(Hacking)**'이란?

↳ 타인의 컴퓨터 시스템에 무단으로 침입해서 정보 또는 권한을 탈취하거나, 시스템을 파괴하는 것   

  즉, 취약한 부분을 찾아내고 이를 공격하는 과정   


## 해킹 주요 분야

해킹 주요 분야는 **3가지 분야**로 나눔  

- **Web Hacking**(웹 해킹): 웹 서비스를 대상으로 하는 분야
- **System Hacking / Pwnable**(시스템 해킹): 프로그램이나 시스템의 취약점을 분석하는 분야
- **Reverse Engineering**(리버스 엔지니어린(=리버싱)): 프로그램을 거꾸로 분석해서 동작 원리를 보는 분야


## '**코딩**'이란?

↳ 프로그래밍 언어를 사용하여 컴퓨터에서 명령할 수 있는 체계를 생성하는 행위로,  
  특정 프로그래밍 언어로 컴퓨터에게 동작을 지시할 수 있음  
  (드림핵에서는 C언어와 Python을 먼저 익히는 것을 권장!)




## 컴퓨터 과학 

↳ 컴퓨터를 이용한 모든 작업과 그 기반 이론을 연구하는 학문으로,  
  코딩뿐만 아니라 계산 이론, 알고리즘, 소프트웨어 설계, 네트워크 등 광범위한 영역을 포함  
  
  이러한 컴퓨터 과학 지식을 응용하여 프로그램이나 시스템의 취약점을 발견하고 공격 행위를 해킹이라고함   

  But, 컴퓨터 과학을 깊게 알아야만 해킹을 배울 수 있는 건 아님  


## '진법'이란?

↳ 한 자릿수에 표현할 수 있는 숫자의 개수  
  즉, 수를 표현하는 방식     

- **n진법**: 한 자릿수를 n가지의 숫자 혹은 문자로 표   ➠  **n진법**으로 나타낸 수는 n진수
- **2진법**: 0과 1로 표현으로 0과 1의 조합을 비트(bit)
- **10진법**: 사람이 일반적으로 쓰는 숫자(0~9) 표현
- **16진법**: 0~9, A~Z를 사용해서 표현(보통 Ox라는 접두어를 붙임)


## '비트'와 '바이트'

'**bit**'는 컴퓨터가 데이터를 표현하는 가장 작은 단위    
'**byte**'는 8개의 bit로 구성된 큰 단위

- **1byte = 8bit**
- bit는 0 또는 1로 표현
- byte 단위는 **파일 크기**, **메모리**, **데이터 표현**에서 자주 사용
- 부호 비트: MSB가 **0**이면 양수, **1**이면 음수


## 바이트 오더링

**2byte 이상**의 테이터를 메모리에 연속적으로 저장할 때 각 바이트가 메모리에 정렬되는 방식

- **Big Endian**(빅 엔디안): **큰** 바이트부터 메모리의 낮은 주소에 저장
- **Little Endian**(리틀 엔디안): **작은** 바이트부터 메모리의 낮은 주소에 저장

  &lt;핵심 Point&gt;
“값이 메모리에 저장되는 순서가 방식에 따라 달라진다”는 점!   


## '비트 연산'이란?

 ↳ 피연산자를 **2진수** 단위로 표현하여 **bit** 단위로 연산하며,   
논리 연산을 수행하거나, 비트를 특정 값만큼 이동하는 **시프트**(shift)연산을 수행

- **논리 연산**: 참(1,true)/거짓(0,false) 기준으로 판단
    =&gt; `||`(or), `&&`(and), `!`(not)
  
- **비트 연산자**: 비트 단위로 연산
   =&gt; `|`(or), `&`(and), `^`(xor), `~`(not)
  
- **시프트 연산자**: 비트를 왼쪽이나 오른쪽으로 이동
    =&gt; `<<`, `>>` (산술 시프트), `>>>` (논리 시프트)
  

## '인코딩'과 '디코딩'

'**인코딩**'은 데이터를 특정 형식으로 변환하는 것  
'**디코딩**'은 변환된 데이터를 원래 값으로 복원하는 것

즉, 데이터를 다른 형식으로 바꾸거나 다시 원래 형태로 되돌리는 과정

- **ASCII**: 문자를 숫자로 표현하는 방식, 미국 표준 코드
- **Unicode**: 여러 나라 문자를 표현하기 위한 표준, 국제 표준 코드
- **URL Encoding**: URL에서 사용할 수 없는 문자를 변환하는 방식  
- **Base64**: 데이터를 문자 형태로 바꿔서 표현하는 방식


## '운영체제(os)'이란?

↳ 컴퓨터의 하드웨어와 소프트웨어 자원을 관리하고, 응용프로그램이 실행될 수 있도록 도와주는 시스템 소프트웨어

- **커널**(Kernel): 운영체제의 핵심 부분, 하드웨어 관리
- **셀**(Shell): 사용자가 명령어를 입력해 운영체제와 상호작용하는 부분

ex) 사용자 ➠ 셀애 명령을 입력 ➠ 셀이 명령어 해석 ➠ 커널에 요청 ➠ 실행 결과 출력

운영체제는 크게 Windows 계열과 UUNIX/Linux 계열로 나누어 볼 수 있음


## '가상 머신(vm)'이란?

↳ 하나의 컴퓨터 안에서 다른 운영체제 환경을 실행하는 기술

  &lt;장점&gt;
- 하나의 컴퓨터에서 여러 운영체제 환경을 사용할 수 있음
- 실습 환경을 실제 PC 환경과 분리할 수 있음
- 실습 중 문재가 생겨도 원래 PC에 미치는 영향을 줄일 수 있음


## '셀(Shell)'이란?

↳ 사용자가 리눅스 시스템을 사용할 수 있게 해주는 명령어 입력 환경

  터미널을 열면 셸을 통해 명령어를 입력할 수 있음

- **Ubuntu/Linux**: `Ctrl + Alt + T`로 터미널 실행 가능
- **macOS**: 기본 터미널 앱 또는 iTerm2 등을 사용
- **Windows**: PowerShell, CMD, Windows Terminal 등을 사용

&lt;셸 프롬프트 예시&gt;

```bash
user@user-VirtualBox:~$
``` 

- `user`: 현재 사용자 이름
- `user-VirtualBox`: 컴퓨터 이름
- `~`: 현재 위치가 홈 디렉토리임을 의미
- `$`: 일반 사용자 권한 상태


## 셀 프롬프트(Shell Prompt)

```bash
user@user-VirtualBox:~$
```


  &lt;핵심 명령어&gt;

- `sudo apt update`: 설치 가능한 소프트웨어 패키지 목록 업데이트
- `sudo apt upgrade`: 설치된 소프트웨어 패키지 버전 업그레이드
- `id`: 현재 유저 ID와 그룹 ID 확인
- `pwd`: 현재 작업 중인 디렉토리 경로 출력
- `ls`: 디렉토리 내용 확인
- `ls -l`: 디렉토리 내용을 자세한 정보와 함께 출력
- `cd`: 디렉토리 이동
- `mkdir`: 디렉토리 생성
- `touch`: 빈 파일 생성
- `mv`: 파일 이동 또는 이름 변경
- `rm`: 파일 삭제
- `rm -r`: 디렉토리 삭제
- `cat`: 파일 내용 출력
- `file`: 파일 유형 확인
- `echo`: 문자열 출력 또는 파일에 저장
- `cp`: 파일 복사
- `cp -r`: 디렉토리 복사
- `grep`: 특정 문자열 검색
- `man`: 명령어 매뉴얼 확인
- `curl`: 서버와 데이터 송수신


&lt;명령어 사용 예시&gt;

```bash
pwd
ls
ls -l
cd /home/user
mkdir test
touch memo.txt
cat memo.txt
```




## '**curl**' 명령어

↳ 서버에 데이터를 보내거나 서버로부터 데이터를 받을 때 사용하는 명령어

&lt;기본 형식&gt;

```bash
curl [옵션] URL
```


  &lt;핵심 옵션&gt;

- `-o 파일명`: 응답 결과를 파일로 저장
- `-i`: 응답 결과에 HTTP 응답 헤더 포함
- `-X "메소드"`: HTTP 요청 메소드 지정
- `-d "key=value"`: POST 요청으로 데이터 전송


&lt;예시&gt;

```bash
curl -i https://example.com
curl -o index.html https://example.com
curl -X POST -d "id=test" https://example.com/login
```

여기서 주의할 점은 HTTP 메소드를 지정할 때 `-x`가 아니라 **대문자** `-X`를 사용한다는 것


## '경로'란?

↳ 리눅스에서 파일이나 디렉토리의 위치를 나타내는 방식

 '**경로**'는 절대 경로와 상대 경로로 나눌 수 있음

  '**절대 경로**'는 `/` 루트 디렉토리부터 전체 위치를 적는 방식

&lt;절대 경로 예시&gt;

```bash
/home/user
/etc/passwd
/var/log
```

  '**상대 경로**'는 현재 위치를 기준으로 이동 경로를 적는 방식

&lt;상대 경로 예시&gt;

```bash
..
./memo.txt
test/file.txt
```


현재 위치는 `pwd` 명령어로 확인할 수 있음


## '와일드카드'이란?

↳ 리눅스에서 파일명이나 문자열을 찾을 때 사용하는 특수 문자

- `?`: 임의의 문자 **1개**
- `*`: 임의의 문자 **0개 이상**
- `[ ]`: **지정한 범위 안**의 문자

파일이 많을 때 특정 패턴에 맞는 파일을 찾는 데 사용 가능!

&lt;예시&gt;

```bash
ls *.txt
ls file?.txt
ls [abc].txt
```

`*.txt`는 `.txt`로 끝나는 모든 파일을 의미함


## '리다이렉션'과 '파이프'

'**리다이렉션**'은 표준 입력이나 표준 출력을 다른 곳으로 바꾸는 작업

즉, 명령어 실행 결과를 화면에만 출력하지 않고 파일로 저장할 수 있음

&lt;예시&gt;

```bash
echo "hello" > memo.txt
cat memo.txt
```

**파이프**는 앞 명령어의 표준 출력을 뒤 명령어의 표준 입력으로 보내는 작업

&lt;예시&gt;

```bash
cat memo.txt | grep hello
```

정리하면

- **리다이렉션**: 결과를 파일로 보내거나 파일에서 입력받음
- **파이프**: 앞 명령어의 결과를 뒤 명령어로 넘김


## '리눅스 권한'이란?

↳ 파일이나 디렉토리에 누가 접근할 수 있는지 정하는 개념  

  &lt;권한을 판단하는 기준&gt;

- 유저(user): 파일 소유자
- 그룹(group): 파일 소유자가 속한 그룹
- other: 그 외 사용자

  &lt;관련 개념&gt;

- UID: 사용자를 구분하는 ID
- GID: 그룹을 구분하는 ID
- `/etc/passwd`: 유저 정보 저장
- `/etc/group`: 그룹 정보 저장


&lt;예시&gt;

```bash
cat /etc/passwd
cat /etc/group
```

사용자가 파일에 접근하면 리눅스는 UID와 GID를 확인해서 권한을 판단함


## 파일 및 디렉토리 권한

권한은 **읽기**, **쓰기**, **실행**으로 구분함

- `r`: 읽기(Read)
- `w`: 쓰기(Write)
- `x`: 실행(Execute)
- `-/`: 권한 없음

권한은 `ls -l` 명령어로 확인 가능!


```bash
drwxrwxr-x 2 user user 4096 12월 2 13:38 dir
```

- `d`: 디렉토리라는 의미
- `rwx`: 소유자 권한
- `rwx`: 그룹 권한
- `r-x`: 그 외 사용자 권한
- `user`: 소유자
- `user`: 소유 그룹
- `dir`: 파일 또는 디렉토리 이름

즉, `dir`의 권한 플래그는 `drwxrwxr-x`이고, 소유자는 `user`, 소유 그룹도 `user`임




## '루트 디렉토리'란?

 ↳ 리눅스의 최상위 디렉토리를 말하며,**절대 경로**는 `/` 

모든 파일과 디렉토리는 루트 디렉토리 아래에 존재함


&lt;루트 디렉토리 확인 명령어&gt;

```bash
cd /;ls -l
```

또는

```bash
ls -l /
```

`ls -l /`를 실행하면 루트 디렉토리 안에 있는 주요 디렉토리를 확인할 수 있음


  &lt;핵심 디렉토리&gt;

- `/bin`: 기본 명령어나 프로그램 저장
- `/boot`: 시스템 부팅에 필요한 파일 저장
- `/dev`: 장치 파일 저장
- `/etc`: 운영체제와 서비스 설정 파일 저장
- `/home`: 일반 사용자의 홈 디렉토리
- `/lib`: 프로그램 실행에 필요한 라이브러리 저장
- `/opt`: 추가 소프트웨어 패키지 저장
- `/proc`: 커널과 프로세스 정보를 파일 형태로 제공
- `/root`: root 사용자의 홈 디렉토리
- `/sbin`: 시스템 관리용 명령어 저장
- `/tmp`: 임시 파일 저장
- `/usr`: 사용자 프로그램, 문서, 라이브러리 저장
- `/var`: 로그처럼 자주 변경되는 파일 저장

&lt;예시&gt;

```bash
/home/dream
```

`dream` 유저의 홈 디렉토리

&lt;예시&gt;

```bash
/var/log
```

시스템 로그 파일이 저장되는 디렉토리


## 'Web Hacking(웹 해킹)'이란?

↳ 웹 상에서 본래의 의도와 다른 동작을 일으키거나 데이터를 악의적인 행위를 수행하는 것   
  ∴ 웹에서 발생할 수 있는 취약점을 알고 방어 대책을 연구하는 것의 중요성이 커지고 있음.


기능이 많고 구조가 복잡할수록 의도하지 않은 동작이나 취약점이 생길 수 있음


 &lt;웹 해킹 중요 Point&gt;

- HTTP와 HTTPS
- HTTP 상태 코드
- GET / POST 메소드 차이
- 로그인 상태 유지 방식
- 사용자 입력값 검증
- 클라이언트와 서버의 역할 차이
- 데이터베이스와 SQL 쿼리 흐름

웹 서비스가 정상적으로 어떻게 동작하는지 먼저 알아야 취약한 부분도 찾을 수 있을 것 같음


## 'Reverse Engineering(리버스 엔지니어링)'이란?

↳ 프로그램을 역으로 분석해서 내부 동작 원리를 파악하는 분야

  줄여서 **Reversing(리버싱)**이라고도 부름

일반적인 개발이 소스 코드를 작성하고 컴파일해서 실행 파일을 만드는 과정이라면,  
리버싱은 반대로 실행 파일이나 바이너리를 보고 프로그램이 어떻게 동작하는지 분석하는 과정

'**리버싱**'은 소스 코드가 없어도 프로그램의 동작을 추측할 수 있다는 점이 중요!

단순히 사람이 읽을 수 있는 코드인지 아닌지만으로 리버싱 여부가 결정되는 것은 아님  
&lt;핵심 Point&gt; 
  프로그램의 동작 원리를 분석하는 과정에 있음



## 'System Hacking(시스템 해킹)'이란?

↳ 프로그램이나 시스템의 취약점을 분석하는 분야

주로 C 언어 기반 프로그램, 메모리 구조, 운영체제 동작 방식과 관련이 많음

'**시스템 해킹**'에서 중요한 점은 프로그램이 시스템 상에서 어떻게 실행되는지 이해하는 것

  &lt;중요하게 Point&gt;

- C 언어 코드 실행 흐름
- 함수 호출 규약
- 스택 프레임 구조
- 레지스터 역할
- 메모리 구조
- 32bit와 64bit 차이
- 어셈블리 코드 해석

특히 스택 버퍼 오버플로우 같은 취약점을 이해하려면  
스택이 어떻게 사용되는지, 함수가 호출될 때 메모리가 어떻게 변하는지 알아야 함!


## 'Cryptography(암호학)'이란?

평문을 암호문으로 바꾸거나, 암호문을 다시 평문으로 복원하는 전반적인 과정


  &lt;중요 Point&gt;

- AND, OR, XOR, NOT 같은 비트 연산
- SHIFT 연산
- 모듈로 연산
- 나머지 계산
- 거듭제곱 계산
- Python 코드 흐름 읽기


## 'Digital Forensics(디지털 포렌식)'이란?

↳ 컴퓨터와 같은 디지털 장치에 저장된 데이터를 수집, 분석, 보존, 해석하여 법적 증거로 활하는 분야

  컴퓨터나 저장장치에 남은 흔적을 분석해서 사건의 흐름을 파악하는 데 사용됨

  단순히 삭제된 파일을 복구하는 것만이 아니라,  
  시스템에 남은 여러 흔적을 통해 어떤 일이 있었는지 분석하는 과정이 중요함




## 'Netcat(nc)'이란?

↳ 클라이언트가 이 프로그램과 통신하기 위해서 사용하는 것
  특정 포트를 통해 서비스를 동작시키는 환경을 구성한 경우   

  &lt;핵심 Point&gt; 

- `nc`는 Netcat 명령어
- 서버와 클라이언트가 TCP 통신할 때 사용 가능
- 웹 브라우저가 아니라 터미널에서 직접 접속하는 방식
- Dreamhack 워게임에서 자주 사용됨


&lt;Netcat 설치 명령어&gt;

```bash
sudo apt update && sudo apt install netcat
```

&lt;기본 사용 형식&gt;

```bash
nc Host Port
```

- `Host`: 접속할 서버 주소
- `Port`: 서버에서 열어둔 통신 번호

브라우저로 접속하는 방식과 다르게  
터미널에서 직접 입력을 보내고 서버의 응답을 확인하는 것이 핵심


&lt;예시&gt;

```bash
nc google.com 80
```

80번 포트는 HTTP 통신에서 자주 사용되는 기본 포트

연결 후 아래처럼 HTTP 요청을 직접 입력할 수 있음

```text
GET / HTTP/1.1
```

이렇게 입력하면 서버에서 응답을 보내는 것을 확인할 수 있음

즉, `nc`는 단순 접속 명령어가 아니라  
서버와 직접 통신해보는 도구에 가까움!


## Flag 제출

↳ 문제 페이지의 Flag 입력 칸에 제출함

  Dreamhack 공식 워게임의 flag 형식

```text
DH{...}
```

제출할 때는 `DH{}`까지 포함해서 전체를 입력해야 함!


## 'SSH'이란?

↳ 원격 Linux 서버(컴퓨터)에 연결할 수 있도록 암호화된 네트워크 프로토콜


워게임이나 CTF 문제에서는 문제 서버에 **직접 접속**해야 하는 경우가 있음  
이때 `ssh` 명령어를 사용해서 원격 서버의 **터미널**에 접속 가능


'**Netcat**'이 서버와 간단히 데이터를 주고받는 느낌이라면,  
'**SSH**'는 원격 서버 안에 직접 로그인해서 터미널을 사용하는 방식에 가까움!


'Windows에서는 OpenSSH 클라이언트가 필요할 수 있음

터미널에서 아래 명령어를 입력했을 때 사용법이 출력되면 준비된 상태

```bash
ssh
```

명령어가 정상적으로 인식되면 SSH 접속 준비 완료


&lt;SSH 기본 형식&gt;

```bash
ssh user@HOST -p PORT -i [개인 키 파일 경로]
```


  &lt;구분 Point&gt;

- `user`: 원격 서버에 존재하는 사용자 이름
- `HOST`: 접속할 서버 주소 또는 도메인
- `PORT`: 접속할 포트 번호
- `-p`: 포트 번호를 지정할 때 사용하는 옵션


&lt;예시&gt;

```bash
ssh user@host3.dreamhack.games -p 11051
```

여기서 Host와 Port는 문제 서버를 생성할 때마다 달라질 수 있음  
∴ 문제 페이지의 접속 정보를 그대로 확인해야 함


&lt;SSH 실습에서 사용한 명령어&gt;

서버에 접속한 뒤 현재 디렉토리의 파일을 확인함

```bash
ls
```

파일 목록에서 `flag` 파일이 보이면 내용을 확인함

```bash
cat flag
```

`cat` 명령어는 파일 내용을 터미널에 출력할 때 사용함


  &lt;실습 흐름&gt;

  SSH로 서버 접속
➠ `ls`로 파일 확인
➠ `cat flag`로 flag 읽기
➠ 출력된 `DH{...}` 형식의 flag 제출


## 'Visual Studio Code'이란?

↳ 코드를 작성할 때 사용하는 소스 코드 편집기

Windows, macOS, Linux에서 사용할 수 있고  
C, Python, JavaScript 등 여러 언어를 작성할 수 있음


&lt;VS Code 핵심 기능&gt;

- Command Palette   [Ctrl+Shift+P]
  : vs code 기능을 검색하여 실행할 수 있는 창
- Terminal   [Ctrl+']
  : vs code 안에서 명령어를 실행할 수 있는 창
- **Extensions**   
- **Explorer**


VS Code를 사용할 때는 파일 편집만 하는 것이 아니라  
터미널에서 명령어를 실행하고 결과를 바로 확인하는 흐름이 중요!


리눅스 VM과 VS Code 연결은 눅스 VM을 따로 사용해도 되지만,  
VS Code와 연결하면 호스트 PC에서 편하게 파일을 수정할 수 있음


&lt;구분 Point&gt;

- **호스트 머신**: 실제 내가 사용하는 컴퓨터
- **게스트 머신**: VM 안에서 실행되는 리눅스 환경

리눅스 VM과 VS Code를 연결하면  
VS Code에서 리눅스 환경의 파일을 직접 열고 수정할 수 있음


WSL 환경에서 VS Code 연결은 WSL을 사용하는 경우 VS Code와 쉽게 연결 가능

먼저 VS Code에서 WSL 확장을 설치함

설치 후 리눅스 환경에서 원하는 디렉토리로 이동한 뒤 아래 명령어 실행

```bash
code .
```

이 명령어를 실행하면 현재 리눅스 디렉토리가 VS Code에서 열림


VirtualBox 환경에서 VS Code 연결은 VirtualBox로 리눅스 VM을 사용하는 경우  
VS Code와 연결하려면 SSH 설정이 필요


WSL보다 설정할 것이 많지만,  
한 번 연결해두면 VS Code에서 리눅스 VM 파일을 편하게 수정할 수 있음


&lt;리눅스 VM 터미널 실행 명령어&gt;

```bash
sudo apt update
sudo apt upgrade
sudo apt-get install openssh-server
```

설치 중 계속 진행할지 물어보면 `y`를 입력함


VirtualBox 포트 포워딩은 호스트 PC와 게스트 VM은 네트워크가 분리되어 있음

그래서 호스트에서 VM의 SSH 서버로 접속하려면 포트 포워딩 설정이 필요함


&lt;포트 포워딩 설정 예시&gt;

```text
이름: ssh
프로토콜: TCP
호스트 포트: 22
게스트 포트: 22
```


&lt;설치 후 Command Palette를 열고 SSH 설정 파일 수정 명령어&gt;

```text
Ctrl + Shift + P
```


&lt;검색할 항목&gt;

```text
Remote-SSH: Open SSH Configuration File
```

기본 config 파일 경로는 보통 아래 위치

```text
~/.ssh/config
```

Windows에서는 사용자 폴더 아래의 `.ssh/config` 파일을 선택하면 됨


SSH config 파일은 접속 정보를 미리 저장해두는 파일


&lt;기본 형식&gt;

```text
Host 접속할_호스트_이름
    HostName IP주소
    Port 포트번호
    User 사용자이름
    IdentityFile 개인키파일경로
```


&lt;예시&gt;

```text
Host linuxvm
    HostName 127.0.0.1
    Port 22
    User user
    IdentityFile ~/.ssh/keyk
```

- `Host`: VS Code에서 보여줄 접속 이름
- `HostName`: 접속할 IP 주소
- `Port`: 접속 포트
- `User`: 리눅스 사용자 이름
- `IdentityFile`: 개인 키 파일 경로

개인 키를 사용하지 않는 경우에는  
패스워드 입력 방식으로 접속할 수 있음


VS Code에서 리눅스 VM 접속은 SSH config 파일을 작성한 뒤 VS Code에서 원격 접속 가능

접속 후에는 VS Code 왼쪽 Explorer에서 리눅스 파일을 확인할 수 있음

Open Folder를 눌러 원하는 디렉토리를 선택하면  
해당 리눅스 디렉토리 안의 파일을 VS Code로 수정 가능


VS Code로 파일 수정는 VS Code로 리눅스 VM에 연결하면,  
리눅스 환경의 파일을 직접 만들고 수정할 수 있음


## C 코드 작성

 VS Code에서 간단한 C 코드를 작성해봄


&lt;예시 코드&gt;

```c
#include <stdio.h>

int main(){
    printf("Hello Beginners!\n");
    return 0;
}
```

이 코드는 `Hello Beginners!`를 출력하고 종료하는 기본 C 프로그램

C 파일은 보통 `.c` 확장자를 사용함


&lt;예시 파일명&gt;

```text
test.c
```


C 코드 컴파일과 실행애서 C 코드는 작성한 뒤 바로 실행되는 것이 아니라  
**컴파일 과정을 거쳐** 실행 가능한 파일로 바꿔야 함

리눅스에서 C 코드를 컴파일할 때는 보통 `gcc`를 사용함


&lt;gcc 버전 확인 명령어&gt;

```bash
gcc --version
```


&lt;gcc 설치 명령어&gt;

```bash
sudo apt install gcc
```


&lt;컴파일 명령어&gt;

```bash
gcc -o test test.c
```

- `gcc`: C 코드 컴파일러
- `-o test`: 실행 파일 이름을 `test`로 지정
- `test.c`: 컴파일할 C 소스 파일


&lt;실행 명령어&gt;

```bash
./test
```


&gt;실행 결과&lt;

```text
Hello Beginners!
```


정리하면,
- `.c` 파일은 소스 코드 파일
- `gcc`로 컴파일해야 실행 가능
- `./파일명`으로 실행 파일 실행 가능

  터미널 에러 메시지 확인
➠ 어느 파일, 몇 번째 줄인지 확인

➠ 코드 수정
➠ 다시 컴파일

## '디버깅'이란?

↳ 코드의 오류를 찾고 수정하는 과정

단순히 코드가 실행되는지만 보는 것이 아니라  
변수 값이 어떻게 변하는지, 어느 줄에서 문제가 생기는지 확인할 수 있음


'**Breakpoint**'는 프로그램을 멈출 지점을 설정하는 것

'**Debug View**'에서 확인 가능한 것

- 변수 값
- Watch 표현식
- Call Stack
- Breakpoints 목록


'**Debug Toolbar**'에서 자주 쓰는 기능

- Continue/Pause: 다음 중단점까지 실행
- Step Over: 함수 내부로 들어가지 않고 다음 줄 실행
- Step Into: 함수 내부로 들어가서 실행
- Step Out: 현재 함수 밖으로 나가기
- Restart: 디버깅 다시 시작
- Stop: 디버깅 종료


## 'Vim'이란?

↳ 리눅스 환경에서 사용할 수 있는 텍스트 편집기

마우스 없이 키보드만으로 파일을 수정할 수 있음


&lt;설치 명령어&gt;

```bash
sudo apt install vim
```

&lt;실행 명령어&gt;

```bash
vi
```

&lt;파일 열기 명령어&gt;

```bash
vi a.txt
```


Vim에는 여러 모드가 있음 (가장 기본적인 모드)

- '**Normal Mode**'는 Vim을 처음 실행했을 때의 기본 모드  
커서 **이동**, **복사**, **삭제** 같은 명령을 수행함

- '**Insert Mode**'는 실제로 텍스트를 입력하는 모드  
일반 편집기처럼 **글자**를 입력할 수 있음

- '**Command Mode**'는 **저장**, **종료**, **검색** 같은 명령을 실행하는 모드


&lt;모드 전환 명령어&gt;

- `esc`: Normal Mode로 돌아가기
- `i`: Insert Mode로 전환
- `:`: Command Mode로 전환


'**Normal Mode**'에서는 커서 이동이나 삭제, 복사 같은 작업을 함


&lt;커서 이동 명령어&gt;

- `h`: 왼쪽으로 이동
- `j`: 아래로 이동
- `k`: 위로 이동
- `l`: 오른쪽으로 이동
- `0`: 행의 처음으로 이동
- `$`: 행의 끝으로 이동
- `gg`: 첫 행으로 이동
- `G`: 마지막 행으로 이동


&lt;삭제, 복사, 붙여넣기 명령어&gt;

- `x`: 현재 커서 위치의 글자 삭제
- `X`: 현재 커서 앞 글자 삭제
- `dd`: 현재 행 삭제
- `yy`: 현재 행 복사
- `p`: 복사한 내용을 현재 행 이후에 붙여넣기
- `P`: 복사한 내용을 현재 행 이전에 붙여넣기


&lt;문자열 찾기 명령어&gt;

- `/문자열` 입력 후 Enter: 현재 커서 이후에서 문자열 찾기
- `n`: 다음 검색 결과로 이동


&lt;되돌리기 명령어&gt;

- `u`: 이전 수정 사항 되돌리기


&lt;Normal Mode에서 Insert Mode로 전환 명령어&gt;

- `i`: 현재 커서 위치에 입력
- `I`: 현재 행의 처음에 입력
- `a`: 현재 커서 다음 위치에 입력
- `A`: 현재 행의 끝에 입력
- `o`: 현재 커서 아래 새 줄을 만들고 입력
- `O`: 현재 커서 위 새 줄을 만들고 입력
- `s`: 현재 커서 글자 지우고 입력
- `S`: 현재 행을 지우고 입력

입력을 끝내고 다시 명령을 사용하려면 `esc`를 눌러 Normal Mode로 돌아감


## 'Docker(도커)'란?

↳ 컨테이너를 만들고 실행할 수 있게 해주는 가상화 플랫폼

CTF나 워게임을 풀다 보면 문제 파일 안에 `Dockerfile`이 제공되는 경우가 있음  
이때 Docker를 사용하면 출제자가 의도한 문제 환경을 거의 그대로 재현할 수 있음


'**Docker**'에서 자주 나오는 개념은 크게 **세 가지**

- '**Docker Image**(도커 이미지)'는 컨테이너를 만들기 위한 기본 틀

이미지 안에는 실행에 필요한 파일, 환경 변수, 명령어, 파일 시스템 등이 들어 있음  
쉽게 말하면 컨테이너를 만들기 위한 준비된 환경이라고 볼 수 있음


- '**Docker Container**(도커 컨테이너)'는 이미지로부터 만들어진 실제 실행 환경

이미지가 실행 전 상태라면, 컨테이너는 실행 중인 상태에 가까움  
컨테이너 안에서는 분리된 파일 시스템과 실행 환경을 사용할 수 있음


- '**Docker Registry**(도커 레지스트리)'는 이미지를 저장하는 저장소

대표적으로 Docker Hub가 있음  
Docker Hub에서 이미지를 다운로드하거나, 직접 만든 이미지를 업로드할 수 있음


&lt;도커를 쓰는 이유&gt;
  Docker는 문제를 풀기 위한 환경을 빠르고 일정하게 만드는 데 사용됨


`docker build`는 Dockerfile을 이용해서 이미지를 생성하는 명령어


&lt;기본 형식&gt;

```bash
docker build [옵션] <경로>
```


&lt;현재 디렉토리에 있는 Dockerfile로 이미지 생성 &gt;

```bash
docker build .
```


&lt;이미지 이름, 태그 지정&gt;

```bash
docker build -t my-image .
```

여기서 `-t` 옵션은 이미지 이름과 태그를 지정할 때 사용함

태그를 따로 지정하지 않으면 보통 `latest`로 지정됨


&lt;빌드가 끝난 뒤 생성된 이미지 확인&gt;

```bash
docker images
```

- `docker build .`: 현재 디렉토리의 Dockerfile로 이미지 생성
- `docker build -t 이름 .`: 이미지 이름 지정해서 빌드
- `docker images`: 생성된 이미지 목록 확인

---

`docker run`은 이미지로 컨테이너를 생성하고 실행하는 명령어


&lt;기본 형식&gt;

```bash
docker run [옵션] <이미지명 또는 ID> [명령어]
```

&lt;포트를 연결 후 실행&gt;

```bash
docker run -p <호스트PORT>:<컨테이너PORT> <이미지명 또는 ID>
```

여기서 `-p` 옵션은 호스트 포트와 컨테이너 포트를 연결할 때 사용함

&lt;컨테이너 안에서 bash 셸을 여는&gt;

```bash
docker run -it <이미지명 또는 ID> /bin/bash
```

-`-it`: 옵션의 의미
- `-i`: 표준 입력을 활성화
- `-t`: 터미널 환경 사용

즉, `-it`는 컨테이너 안에서 명령어를 직접 입력할 수 있게 해주는 옵션


&lt;실행 중인 컨테이너 목록 확인&gt;

```bash
docker ps
```


&lt;종료된 컨테이너까지 모두 확인&gt;

```bash
docker ps -a
```


&lt;구분 Point&gt;

- `docker ps`: 실행 중인 컨테이너만 출력
- `docker ps -a`: 종료된 컨테이너까지 모두 출력

컨테이너 안에서 `exit`를 입력하면 컨테이너가 종료됨

종료 후 `docker ps`를 실행하면 목록에 보이지 않을 수 있음  
하지만 `docker ps -a`를 실행하면 종료된 컨테이너까지 확인 가능


`docker run`은 컨테이너 생성과 실행을 한 번에 수행함

반대로 생성과 실행을 따로 할 수도 있음

&lt;컨테이너 생성&gt;

```bash
docker create [옵션] <이미지명 또는 ID> [명령어]
```

&lt;중단된 컨테이너 시작&gt;

```bash
docker start [옵션] <컨테이너명 또는 ID>
```

---

`docker run`은 간단한 실습에서 편하고,  
`docker create`와 `docker start`는 컨테이너 생성과 실행을 구분하고 싶을 때 사용함

---

`docker exec`는 실행 중인 컨테이너에 접속해서 명령어를 수행하는 명령어


&lt;기본 형식&gt;

```bash
docker exec [옵션] <컨테이너명 또는 ID> [명령어]
```


&lt;실행 중인 컨테이너에서 bash 셸 열기&gt;

```bash
docker exec -it <컨테이너명 또는 ID> /bin/bash
```

- `docker run -it`와 비슷하게 보이지만 차이가 있음
- `docker run`: 새 컨테이너를 생성하고 실행
- `docker exec`: 이미 실행 중인 컨테이너 안으로 들어감
  

&lt;실행 중인 컨테이너를 중단할 때&gt;

```bash
docker stop <컨테이너명 또는 ID>
```


&lt;Docker Hub에 있는 이미지를 다운로드할 때&gt;

```bash
docker pull <이미지명>
```


&lt;예시&gt;

```bash
docker pull ubuntu:18.04
```


&lt;컨테이너 삭제&gt;

```bash
docker rm <컨테이너명 또는 ID>
```


&lt;이미지 삭제&gt;

```bash
docker rmi <이미지명 또는 ID>
```


&lt;이미지 또는 컨테이너의 자세한 정보 확인&gt;

```bash
docker inspect <이미지명 또는 컨테이너명 또는 ID>
```

&lt;핵심 정리&gt;

- `docker pull`: 이미지 다운로드
- `docker rm`: 컨테이너 삭제
- `docker rmi`: 이미지 삭제
- `docker inspect`: 자세한 정보 확인


## Docker 컨테이너 안에서 문제 확인

&lt;컨테이너에 접속한 뒤 파일 목록 확인&gt;

```bash
ls
```


&lt;문제 파일이 있으면 실행 가능&gt;

```bash
./chall
```


&lt;flag 파일이 있으면 내용 확인&gt;

```bash
cat flag
```

이번 실습에서는 컨테이너 안에 `chall`과 `flag` 파일이 존재함


&lt;컨테이너에서 빠져나올 때&gt;

```bash

```


&lt;종료된 컨테이너 확인&gt;

```bash
docker ps -a
```


&lt;종료된 컨테이너를 다시 실행&gt;

&lt;정리&gt;

- 컨테이너 안에서도 일반 리눅스 명령어 사용 가능

- 종료된 컨테이너는 `docker ps -a`로 확인 가능
- `docker start`와 `docker exec`로 다시 접속 가능




## 'Dockerfile'이란?

 ↳ Docker 이미지를 만들기 위한 설정 파일

이미지를 생성하는 데 필요한 명령어가 순서대로 작성되어 있음  
운영체제, 환경 변수, 파일 복사, 권한 설정, 실행 명령어 등을 정의할 수 있음

'**Dockerfile**'의 기본 파일명은 확장자 없이 `Dockerfile`

`docker build`를 실행하면 현재 디렉토리에서 '**Dockerfile**'을 찾아 이미지를 빌드함


&lt;Dockerfile 기본 구조&gt;

```dockerfile
# 주석
명령어 인자

FROM ubuntu:18.04
```

'**Dockerfile**'은 보통 `FROM` 명령어로 시작함


`FROM`은 이미지의 기반이 되는 base 이미지를 지정함

```dockerfile
FROM ubuntu:18.04
```

Ubuntu 18.04 이미지를 기반으로 새 이미지를 만든다는 의미


`ENV`는 Dockerfile 안에서 사용할 환경 변수를 지정함

```dockerfile
ENV user chall
ENV chall_port 2222
```

파일 안에서 변수는 아래처럼 사용할 수 있음

```dockerfile
$변수명
${변수명}
```

예를 들어 `ENV user chall`로 지정하면  
이후 Dockerfile 안에서 `$user`를 사용할 수 있음


`RUN`은 이미지를 빌드할 때 실행할 명령어를 작성함

```dockerfile
RUN apt-get update
RUN ["/bin/bash", "-c", "echo hello"]
```

패키지를 설치하거나 권한을 설정할 때 자주 사용함


`COPY`는 로컬 파일이나 디렉토리를 이미지 파일 시스템 안으로 복사함

```dockerfile
COPY <src> <dest>
```


`ADD`도 파일이나 디렉토리를 이미지 파일 시스템 안으로 복사함

```dockerfile
ADD <src> <dest>
```


`WORKDIR`은 '**Dockerfile**' 안에서 명령어가 실행될 작업 디렉토리를 지정함

```dockerfile
WORKDIR /home/user
```

리눅스의 `cd` 명령어와 비슷하게 이해하면 됨


`USER`는 이후 명령을 실행할 사용자 또는 그룹을 지정함

```dockerfile
USER $username
```


`EXPOSE`는 컨테이너가 사용할 포트를 지정함

```dockerfile
EXPOSE 80/tcp
```

컨테이너가 외부에서 들어오는 네트워크 요청을 받을 포트를 표시하는 역할




`ENTRYPOINT`는 컨테이너가 실행될 때 수행할 기본 명령어를 지정함

```dockerfile
ENTRYPOINT ["echo", "hello"]
```


`CMD`는 컨테이너가 실행될 때 수행할 명령어를 지정하거나,  
`ENTRYPOINT`에 전달할 인자를 지정함

```dockerfile
CMD ["echo", "hello"]
```

`ENTRYPOINT`와 `CMD`를 함께 사용할 수도 있음


&lt;예시&gt;

```dockerfile
ENTRYPOINT ["python"]
CMD ["app.py"]
```

이 상태에서 컨테이너를 실행하면 기본적으로 아래 명령어가 실행됨

```bash
python app.py
```

만약 실행할 때 인자를 바꾸면 `CMD` 부분이 바뀔 수 있음



&lt;정리&gt;

- `ENTRYPOINT`: 컨테이너 실행 시 기본 실행 명령 지정
- `CMD`: 기본 인자 또는 기본 명령 지정
- `CMD`는 여러 개 있으면 마지막 `CMD`가 적용됨
- `docker run`에서 인자를 주면 `CMD`가 바뀔 수 있음




## 'Docker Hub'이란?

↳ '**Docker**'의 공식 레지스트리

'**Docker**' 이미지를 저장하고 공유할 수 있는 저장소

&lt;Docker Hub에서 할 수 있는 것&gt;

- 공식 이미지 다운로드
- 다른 사용자가 올린 이미지 다운로드
- 직접 만든 이미지 업로드
- 이미지 버전 관리
- 팀원과 이미지 공유

대표적으로 Ubuntu, CentOS 같은 운영체제 이미지나  
프로그래밍 언어 개발 환경 이미지 등을 가져올 수 있음


'**Docker Hub**'에 이미지를 업로드하려면 먼저 로그인해야 함

```bash
docker login
```


이미지를 빌드할 때 저장소 이름과 태그를 지정함

```bash
docker build -t <사용자명>/<레포지토리명>:[TAG] <Dockerfile 경로>
```


이미지를 '**Docker Hub**'에 업로드

```bash
docker push <사용자명>/<레포지토리명>:[TAG]
```

&lt;핵심 Point&gt;

- `docker login`: Docker Hub 로그인
- `docker build -t`: 이미지 이름과 태그 지정해서 빌드
- `docker push`: 이미지를 Docker Hub에 업로드




## 정규 표현식이란?
↳ 특정한 패턴으로 문자열을 표현하는 식

**정규 표현식**은 Regular Expression이라고 부름

여기서'**패턴**'은 어떤 문자 조합을 식으로 나타낸 것
정규 표현식에 부합하는 문자열의 경우 ➠ **정규 표현식** or 패턴에 '**매치한다**'라고 표현


&lt;이메일 정규 표현식 예시&gt;

`^[\w-\.]+@([\w-]+\.)+[\w-]{2,4}$`

이 '**정규 표현식**'은 이메일처럼 보이는 문자열과 매치됨


&lt;매치되는 예시&gt;

```text
xxx@xxx.xxx
```


&lt;매치되지 않는 예시&gt;

```text
xxx@xxx.x
```

'**정규 표현식**'에서 중요한 점은  
전체 문자열이 원하는 형식과 맞는지 확인할 수 있다는 것

이메일뿐만 아니라 전화번호, 주민등록번호, URL, flag 형식 등을 검사할 때도 사용 가능!



정규 표현식은 주로 로직을 수행하기 전, 이용자가 입력한 값을 검증하기 위해 사용됨

- 이메일 형식 확인
- 전화번호 형식 확인
- URL 형식 확인
- 특정 단어 검색
- 로그에서 필요한 값 추출
- flag 형식 찾기
등의 입력 값이 특정 형식이어야 하는 모든 경우에 유용하게 사용됨


&lt;Dreamhack flag는 형식&gt;

```text
DH{...}
```


&lt;더 쉽개 플래그를 찾는 형식&gt;

```text
DH\{.+\}
```

여기서 `{`와 `}`는 정규 표현식에서 특별한 의미를 가질 수 있으므로  
문자 그대로 사용하려면 `\`로 이스케이프해야 함


&lt;정규 표현식 작성 형태&gt;

```text
'패턴' 혹은 /패턴/
```


옵션까지 같이 작성할 때는 아래처럼 작성함

```text
/패턴/플래그
```


&lt;예시&gt;

```text
/[0-9]+/g
```

여기서 `/[0-9]+/`는 숫자가 1개 이상 반복되는 패턴  
`g`는 전체 문자열에서 모든 매치를 찾겠다는 의미


**정규 표현식 패턴**

&lt;**매치**&gt;
- `.` : 임의의 문자 1개와 매치
- `|` : 앞 또는 뒤 패턴과 매치
- `[]` : 대괄호 안에 있는 문자 중 하나와 매치
- `[^]` : 대괄호 안의 문자를 제외한 나머지와 매치
- `^` : 문자열의 시작과 매치
- `$` : 문자열의 끝과 매치
- `\` : 특수 문자를 문자 그대로 사용하기 위한 이스케이프
- `[a-z]` : 소문자 알파벳 범위
- `[A-Z]` : 대문자 알파벳 범위
- `[0-9]` : 숫자 범위
- `\w` : 알파벳, 숫자, 언더스코어와 매치
- `\d` : 숫자와 매치
- `\s` : 공백 문자와 매치


'**수량자**'는 앞에 나온 문자가 몇 번 반복되는지를 나타냄

&lt;**수량자**&gt;
- `*` : 0번 이상 반복
- `+` : 1번 이상 반복
- `?` : 0번 또는 1번
- `{n}` : 정확히 n번 반복
- `{n,}` : n번 이상 반복
- `{n1,n2}` : n1번 이상 n2번 이하 반복


&lt;**그룹화**&gt;
- `()` : 소괄호 안에 있는 문자를 하나의 문자처럼 그룹화

'**그룹화**'는 단순히 묶는 것뿐만 아니라  
매치된 문자열의 특정 부분을 따로 추출할 때도 사용됨


정규 표현식의 **수량자**는 기본적으로 '**탐욕적 수량자**'이며,
'**탐욕적 수량자**'는 가능한 많은 문자를 매치하려고 함

'**게으른 수량자**'는 탐욕적 수향자로 인한 과한 매치를 막기 위해 등장한 것

게으른 수량자는 수량자 뒤에 `?`를 붙임

&lt;예시&gt;

```text
<.*>
```

이 패턴은 `<p>Hi!</p>` 전체를 한 번에 매치할 수 있음

반대로 게으른 수량자는 가능한 적은 문자만 매치함

```text
<.*?>
```

이 패턴은 `<p>`처럼 가장 짧게 매치되는 부분부터 찾음

&lt;구분 Point&gt;
- `.*` : 가능한 많이 매치
- `.*?` : 가능한 적게 매치


## '플래그'란?

↳ 정규 표현식의 검색 옵션을 지정하는 역할

&lt;**flags**&gt;
- `i` : 대소문자 구분 없이 검색
- `s` : `.`이 줄바꿈 문자까지 포함하도록 검색
- `m` : 여러 줄 기준으로 검색
- `g` : 전체 문자열에서 모든 매치 검색
  

Python에서는 `re` 모듈을 사용해서 정규 표현식을 다룸

&lt;사용 명령어&gt;

```python
import re
```

&lt;**re 모듈 함수**&gt;
- `re.compile()` : 정규 표현식 패턴을 미리 컴파일
- `re.search()` : 문자열 전체에서 처음으로 매치되는 부분 검색
- `re.match()` : 문자열 시작 부분에서 매치되는지 확인
- `re.fullmatch()` : 전체 문자열이 패턴과 정확히 일치하는지 확인
- `re.findall()` : 매치되는 모든 문자열을 리스트로 반환
- `re.finditer()` : 매치 객체를 반복 가능한 형태로 반환


&lt;예시&gt;

```python
import re

result = re.findall('[A-Z]', 'Hello, DreamHack!')

print(result)
```

&gt;결과&lt;

```text
['H', 'D', 'H']
```

위 코드는 문자열에서 알파벳 대문자만 찾아 리스트로 반환함!


## JavaScript에서 정규 표현식 사용

↳ **두 가지 방식**으로 작성할 수 있음

**1. 정규 표현식 리터럴 방식**

```javascript

```

플래그를 붙이면 아래처럼 작성함


**2. `RegExp` 객체를 생성하는 방식**

```javascript
new RegExp('패턴', '플래그')
```

&lt;**Javascript 정규 표현식 함수**&gt;
- `pattern.exec(string)` : 패턴에 처음 매치되는 문자열 정보 반환
- `pattern.test(string)` : 매치되면 `true`, 아니면 `false` 반환
- `string.match(pattern)` : 매치되는 문자열을 배열로 반환


&lt;예시&gt;

```javascript
const r = /\d/g;

const str = 'H3ll0, DreamH4ck!';

console.log(result);
```

&gt;결과&lt;

```text
['3', '0', '4']
```

위 코드는 문자열에서 숫자만 찾아 배열로 반환함

## '마크다운(Markdown)' 문법

↳ 마크업 언어의 한 종류
↳ 마크업 언어는 문서나 데이터의 구조를 표시하기 위한 언어  

웹페이지를 구성하는 HTML도 마크업 언어에 해당함

'**Markdown**'은 HTML보다 훨씬 간단한 문법으로 문서를 작성할 수 있음

예를 들어 제목을 만들 때 HTML에서는 아래처럼 작성함

```html
<h1>제목</h1>
```

Markdown에서는 아래처럼 작성 가능

```markdown
# 제목
```

즉, '**Markdown**'은 문서를 빠르게 작성하고 읽기 쉽게 정리하기 위한 문법이라고 볼 수 있음!


Markdown을 사용하면 글의 구조를 쉽게 잡을 수 있음

  &lt;**Markdown**으로 할 수 있는 것&gt;

- 제목 만들기
- 문단 나누기
- 줄바꿈
- 글씨 굵게 표시
- 기울임 표시
- 목록 작성
- 코드 작성
- 링크 추가
- 이미지 삽입
- 인용문 작성


Markdown 파일은 보통 `.md` 확장자를 사용함

&lt;예시&gt;

```text
README.md
dream-beginners.md
docker-study.md
```

VS Code에서 `.md` 파일을 만들고 작성하면 Markdown 문법을 사용할 수 있음

작성 결과를 확인하려면 **VS Code**에서 미리보기를 열면 됨

&lt;VS Code 미리보기&gt;

```text
돋보기가 포함된 스플릿(Open Preview to the Side)
```

Markdown은 작성한 문법이 바로 눈에 보이는 방식은 아니지만,  
미리보기를 통해 실제 출력 결과를 확인할 수 있음


'**Headings**'은 제목이나 소제목을 만들 때 사용함

`#` 기호를 사용하고, `#`의 개수에 따라 제목 크기가 달라짐

```markdown
# Heading level 1
## Heading level 2
### Heading level 3
#### Heading level 4
##### Heading level 5
###### Heading level 6
```

&lt;주의할 Point&gt;

- `#` 뒤에는 공백을 넣어야 함
- `#제목`보다 `# 제목` 형태로 작성하는 것이 좋음
- `#` 개수가 많아질수록 더 작은 제목이 됨


블로그 글에서는 보통 아래처럼 사용하면 됨

```markdown
# 글 제목
## 큰 주제
### 세부 내용
```

정리할 때는 제목 단계를 너무 많이 나누기보다  
`##`, `###` 정도를 중심으로 쓰는 것이 보기 좋음


'**Paragraphs**'은 글의 내용을 구분하는 단위

'**Markdown**'에서는 엔터 한 번만 치면 화면에서 줄바꿈이 적용되지 않을 수 있음

문단을 나누려면 한 줄을 비워야 함

```markdown
첫 번째 문단입니다.

두 번째 문단입니다.
```

블로그에서는 이렇게 문단이 분리되어 보임

&lt;중요 Point&gt;

- 엔터 한 번은 같은 문단으로 이어질 수 있음
- 문단을 나누려면 엔터를 두 번 눌러 한 줄을 비워야 함
- 글을 읽기 쉽게 하려면 문단을 적절히 나누는 것이 좋음


'**Line Break**'은 같은 문단 안에서 줄만 바꾸고 싶을 때 사용함

**줄바꿈**을 **강제**로 적용하려면 문장 끝에 **공백 두 칸**을 넣고 **엔터**를 누름

```markdown
첫 번째 줄  
두 번째 줄
```

정리하면,   

- 문단 분리: 엔터 두 번
- 같은 문단 안 줄바꿈: 공백 두 칸 + 엔터


'**Text Styles**'은 글씨 스타일을 바꿀 때는 `*`, `_`, `~` 등을 사용함


```markdown
**굵은 글씨**
*기울임 글씨*
***굵고 기울임***
~~취소선~~
```


 '**Blockquote**'는 인용문을 작성할 때 사용함

&lt;`>` 기호를 사용해서 작성함&gt;

```markdown
> 인용문입니다.
```


&lt;여러 줄도 작성 가능&gt;

```markdown
> 첫 번째 인용문
> 두 번째 인용문
```


&lt;중첩 인용문&gt;

```markdown
> 바깥 인용문
>> 안쪽 인용문
```

보통 참고 문장, 중요 문장, 따로 강조하고 싶은 설명을 넣을 때 사용 


'**Lists**'은 내용을 나열할 때 사용함

&lt;순서가 없는 목록은 `-`, `*`, `+` 중 하나를 사용&gt;

```markdown
- 첫 번째 항목
- 두 번째 항목
- 세 번째 항목
```


&lt;순서가 있는 목록은 숫자를 사용&gt;

```markdown
1. 첫 번째
2. 두 번째
3. 세 번째
```


&lt;목록 안에 하위 항목을 넣는 경우&gt;

```markdown
- Docker
  - Image
  - Container
  - Registry
```

&lt;주의할 Point&gt;

- 하위 항목은 들여쓰기 필요
- 보통 스페이스 2칸 또는 4칸을 사용
- 같은 글 안에서는 한 방식으로 통일하는 것이 좋음


'**Codes**'를 표시하는 방법은 두 가지

짧은 코드나 명령어는 백틱 **1개**를 사용함

```markdown
`docker build`
```


&lt;예시&gt;

```markdown
Docker 이미지는 `docker build` 명령어로 생성함
```

여러 줄 코드는 백틱 **3개**를 사용함


## 'Introduction to Reverse Engineering'이란?

↳ 엔지니어링을 역으로 한다는 의미로,
이미 만들어진 프로그램을 거꾸로 분석해서 프로그램의 구조와 동작 원리를 파악하는 과정

일반적인 소프트웨어 엔지니어링은 프로그램을 설계하고 만드는 과정이라면,  
리버스 엔지니어링은 만들어진 프로그램을 분석해서 내부 동작을 이해하는 과정이라고 볼 수 있음!


&lt;**핵심!**&gt;
- 리버스 엔지니어링은 줄여서 리버싱이라고도 부름
- 완성된 프로그램을 분석하는 과정
- 소스 코드가 없어도 프로그램 동작을 추측할 수 있음
- 프로그램이 어떻게 만들어졌는지, 어떻게 동작하는지 이해하는 것이 목표

즉, 리버싱은 단순히 프로그램을 실행해보는 것이 아니라  
프로그램의 내부 구조를 분석하면서 동작 원리를 찾아가는 학습에 가까움





## 동적 분석과 정적 분석

리버스 엔지니어링에서는 프로그램을 분석하는 방법을 크게 **두 가지**로 볼 수 있음


'**동적 분석**'은 프로그램을 직접 실행하면서 동작을 확인하는 방식

'**정적 분석**'은 프로그램을 실행하지 않고 분석하는 방식





## 프로그램이란?

프로그램은 컴퓨터에게 특정 작업을 수행하도록 지시하는 명령어들의 집합


리버스 엔지니어링에서는 프로그램을 단순히 사용하는 것이 아니라  
프로그램이 내부적으로 어떻게 동작하는지 분석해야 함


'**확장자**'는 파일 이름 뒤에 붙는 문자열로, 파일의 종류를 나타내는 표시

&lt;예시&gt;

```text
hello.txt
program.exe
image.png
archive.zip
```

여기서 `.txt`, `.exe`, `.png`, `.zip` 같은 부분이 확장자

'**확장자**'는 파일이 어떤 종류인지 사람이 쉽게 구분하기 위해 사용됨

&lt;**확장자**&gt;

- `.txt`: 일반 텍스트 파일
- `.doc`, `.docx`: Word 문서 파일
- `.pdf`: PDF 문서 파일
- `.jpg`, `.png`, `.gif`: 이미지 파일
- `.exe`: Windows 실행 파일
- `.msi`: Windows 설치 파일
- `.bat`: Windows 배치 파일
- `.zip`: 압축 파일


중요한 점은 확장자가 파일의 실제 내용을 완전히 보장하지는 않는다는 것




## 실행 파일과 텍스트 파일의 차이

`.txt` 파일은 사람이 읽을 수 있는 텍스트를 저장하는 파일

반면 `.exe` 파일은 Windows에서 실행 가능한 프로그램 파일

겉으로는 파일처럼 보이지만 내부 데이터 구조가 다름

&lt;이유&gt;

- 실행 파일은 일반 텍스트가 아님
- 컴퓨터가 해석할 수 있는 바이너리 데이터로 저장됨
- 사람이 바로 읽기 어렵기 때문에 별도의 분석 도구가 필요함

따라서 실행 파일을 분석할 때는 메모장보다  
HxD 같은 헥스 편집기를 사용해서 내부 데이터를 확인하는 것이 적절함




## 컴퓨터의 데이터 저장 방식

컴퓨터는 모든 데이터를 숫자로 저장함

사람은 문자, 이미지, 프로그램을 서로 다르게 인식하지만  
컴퓨터 내부에서는 결국 숫자 데이터로 처리됨

가장 기본이 되는 표현 방식은 **2진법**

'**2진법**'은 컴퓨터가 데이터를 저장하고 처리하는 기본 방식으로
              `0`과 `1`만 사용해서 데이터를 표현하는 방식

&lt;**2진수 예시**&gt;

```text
2진수: 1011 1110 1001
```


&lt;**16진수 예시**&gt;

```text
16진수: 0xBE9
```

'**16진수**'는 '2진수'보다 **짧게** 표현할 수 있어서  
바이너리 데이터를 확인할 때 많이 사용됨


&lt;정리!&gt;

- 2진법: `0`과 `1`로 표현
- 16진법: `0~9`, `A~F`로 표현
- 16진수는 보통 `0x`를 앞에 붙여 표시
- 16진수는 바이너리 데이터를 짧게 표현하기 좋음


&lt;예시&gt;

```text
2진수 11111111 = 16진수 FF
```

리버싱에서는 파일 내부 데이터를 볼 때  
16진수 형태로 보는 경우가 많기 때문에 익숙해질 필요가 있음


'**ASCII**'는 문자를 숫자로 표현하기 위한 문자 인코딩 방식

컴퓨터는 문자를 그대로 저장하지 않고,  
각 문자에 대응되는 숫자 값을 저장함

&lt;예시&gt;

```text
문자 A = 10진수 65
문자 A = 16진수 0x41
```

즉, 사람이 보는 `A`라는 문자는 컴퓨터 내부에서는 숫자 값으로 저장됨!


'**HxD편집기**'는 파일의 바이너리 데이터를 16진수 형태로 볼 수 있는 헥스 편집기

일반 텍스트 편집기로는 실행 파일 내부를 제대로 보기 어렵지만,  
HxD를 사용하면 파일이 실제로 어떤 바이트 값으로 구성되어 있는지 확인할 수 있음

&lt;HxD에서 볼 수 있는 것&gt;

- 파일의 16진수 데이터
- 해당 데이터의 ASCII 표현
- 파일의 시작 부분
- 실행 파일의 헤더 정보


'**헤더(Header)**'는 파일이나 데이터의 앞부분에 위치한 정보

파일의 종류, 구조, 실행 방식과 관련된 정보가 들어 있을 수 있음

Windows 실행 파일의 경우 파일 앞부분에 `MZ` 헤더가 존재함

HxD에서 보이는 값

```text
4D 5A
```

이 값은 ASCII 문자로 보면 아래와 같음

```text
MZ
```

&lt;중요한 점&gt;

- 파일의 앞부분에는 파일을 해석하는 데 필요한 정보가 들어 있을 수 있음
- 실행 파일은 특정한 헤더 구조를 가질 수 있음
- 헤더를 확인하면 파일 종류를 추측할 수 있음

파일 확장자만 보는 것보다  
파일 헤더를 확인하는 것이 더 정확한 경우가 있음


'**어셈블리어**'는 컴퓨터가 실행해야할 명령어를 담은 데이터 

컴퓨터가 실제로 실행하는 명령은 사람이 이해하기 어렵기 때문에  
이를 사람이 조금 더 읽기 쉽게 표현한 것이 어셈블리어라고 볼 수 있음


&lt;예시&gt;

```asm
nop
```

`nop`은 아무 작업도 하지 않는 명령어


&lt;예시&gt;

```asm
mov rax, 0x1302 
```

`mov rax,  0x1302` - `rax`라고 불리는 저장 공간에 0x1302 값을 저장하는 명령어


&lt;'기계어' ➠ '어셈블리어' 예&gt;

- `48 C7 C0 02 13 00 00` ➠ `mov rax, 0x1302`
- `48 83 c3 05` ➠ `add rbx, 5`
- `0f 84 ae 00 00 00` ➠ `je 0xb4`


&lt;핵심정리!&gt;

- 기계어: 컴퓨터가 직접 실행하는 숫자 데이터
- 어셈블리어: 기계어를 사람이 읽기 쉽게 표현한 형태
- 리버싱 도구는 기계어를 어셈블리어로 변환해서 보여줌





## '소스 코드' 작성하기

↳ 사람이 읽고 이해할 수 있는 프로그램 코드

&lt;파일 생성 및 열기&gt;

```bash
vi helloworld.c
```

`vim` 편집기가 열리면 처음에는 내용이 없는 상태

코드를 입력하려면 `i`를 눌러 입력 모드로 들어감

입력 모드로 들어가면 화면 아래에 아래와 같이 표시됨

```text
INSERT
```

이 상태에서 코드를 작성할 수 있음


&lt;Hello World c언어 코드&gt;

```c
#include <stdio.h>

int main() {
    printf("Hello World!\n");
}
```

&lt;코드 의미&gt;

- `#include <stdio.h>`: 표준 입출력 함수를 사용하기 위한 헤더 파일 포함
- `int main()`: 프로그램이 시작되는 함수
- `printf()`: 문자열을 화면에 출력하는 함수
- `\n`: 줄바꿈 문자




&lt;Vim에서 저장하고 종료하는 흐름&gt;

`ESC` 키를 눌러 일반 모드로 돌아감 ➠ `:wq` 입력 ➠ Enter

```text
:wq
```

&lt;의미&gt;

- `w`: 저장
- `q`: 종료
∴ `wq`: 저장하고 종료

저장 후 파일 내용을 확인할 때는 `cat` 명령어 사용

```bash
cat helloworld.c
```

`cat`을 사용하면 작성한 소스 코드가 터미널에 출력됨


비유하면, 사람과 컴퓨터 사이의 번역기

'**컴파일**'은 사람이 작성한 소스 코드를 컴퓨터가 실행할 수 있는 실행 파일로 바꾸는 과정

비유하면, 사람과 컴퓨터 사이의 번역기


C 언어에서는 보통 `gcc` 컴파일러를 사용함

&lt;컴파일 명령어&gt;

```bash
gcc helloworld.c -o helloworld
```


&lt;의미&gt;

- `gcc`: C 언어 컴파일러
- `helloworld.c`: 컴파일할 소스 코드 파일
- `-o helloworld`: 생성할 실행 파일 이름을 `helloworld`로 지정

컴파일이 성공하면 `helloworld`라는 실행 파일이 생성됨


&lt;파일 목록 확인&gt;

```bash
ls
```

정상적으로 컴파일되었다면 `./helloworld` 파일을 확인할 수 있음


'**프로그램 실행**'은 리눅스에서 현재 디렉토리에 있는 실행 파일을 실행할 때는 `./`를 붙임

&lt;실행 명령어&gt;

```bash
./helloworld
```

&gt;실행 결과&lt;

```text
Hello world!
```


&lt;정리할 것&gt;

- 소스 코드 파일: `helloworld.c`
- 실행 파일: `helloworld`
- 실행 명령어: `./helloworld`

`gcc`로 컴파일한 뒤 실행 파일을 실행하면  
소스 코드에 작성한 `printf()`의 결과가 출력됨!


실행 파일을 `cat`으로 열면 알아보기 어려운 문자들이 출력됨

```bash
cat helloworld
```


즉, `helloworld.c`는 사람이 읽는 소스 코드이고,  
`helloworld`는 컴퓨터가 실행하는 바이너리 파일임!


실행 파일을 사람이 조금 더 보기 쉽게 확인하려면 `xxd`를 사용

```bash
xxd helloworld
```

`xxd`는 파일의 내용을 16진수 형태로 보여주는 도구

출력이 너무 길면 앞부분만 확인할 수 있음

&lt;실행 명령어&gt;
```bash
xxd helloworld | head -3
```


&gt;실행 결과&lt;
```text
7f 45 4c 46
```


Windows의 실행 파일이 `.exe` 형식이라면,  
Linux에서는 ELF 형식의 실행 파일이 사용됨


&lt;**중요 Point**&gt;

- Windows 실행 파일: 보통 `.exe`
- Linux 실행 파일: 보통 ELF 형식
- ELF 파일은 앞부분에 `7f 45 4c 46` 값이 나타남
- ASCII로 보면 `.ELF`로 확인 가능

실행 파일은 단순한 문자열이 아니라  
운영체제가 읽고 실행할 수 있는 구조를 가진 파일임

리버싱에서는 이런 실행 파일을 분석해서  
프로그램이 어떤 동작을 하는지 파악하게 됨


## 리버스 엔지니어링(Reverse Engineering)
↳ 엔지니어링 과정을 역으로 수행하면서 제품 동작 원리와 제품 기술들을 파악하는 과정

**연공학** or 줄여서 '**리버싱**' 이라고 칭함

분석 방법은 크게 두가지로 나눌 수 있음

'**동적 분석(Dynamic Analysis)**'은 프로그램을 직접 실행하면서 분석하는 방식  

&lt;실습 파일 다운로드 명령어&gt;

```bash
wget "https://dreamhack-lecture.s3.amazonaws.com/uploads/reversing/intro/main"
```


&lt;파일 실행 명령어&gt;

```bash
./main
```


&gt;실행 결과&lt;

```text
password:
```


숫자를 넣어보면 프로그램이 입력값을 변환해서 비교하는 것을 확인할 수 있음


&lt;예시&gt;

```text
password: 00000000
output: 0xb9 0xb9 0xb9 0xb9 0xb9 0xb9 0xb9 0xb9
wanted: 0x62 0xb1 0xb7 0xee 0xe8 0x65 0xee 0xe3
0/8 correct. Wrong password...
```

&lt;확인 Point&gt;

- `output`은 내가 입력한 값이 변환된 결과
- `wanted`는 프로그램이 원하는 정답 값
- 두 값이 같아야 올바른 패스워드가 됨

이번에는 `11111111`을 입력해봄


&gt;결과&lt;

```text
password: 11111111
output: 0x62 0x62 0x62 0x62 0x62 0x62 0x62 0x62
wanted: 0x62 0xb1 0xb7 0xee 0xe8 0x65 0xee 0xe3
1/8 correct. Wrong password...
```


첫 번째 값이 `wanted`와 같아졌기 때문에  
숫자 `1`은 `0x62`로 변환된다는 것을 알 수 있음

즉, 입력한 숫자마다 특정한 `output` 값으로 변환되는 구조로 보임


'**output**'는 숫자 0부터 9까지 각각 어떤 값으로 변환되는지 확인하면 패스워드를 찾을 수 있음

&lt;`입력 숫자` ➠ `output`&gt;          |         &lt;`output` ➠ `입력 숫자`&gt;
                                  |
   - `0` ➠ `0xb9`                |             - `0xb9` ➠ `0` 
   - `1` ➠ `0x62`                |             - `0x62` ➠ `1` 
   - `2` ➠ `0xee`                |             - `0xee` ➠ `2`  
   - `3` ➠ `0x65`                |             - `0x65` ➠ `3` 
   - `4` ➠ `0x3b`                |             - `0x3b` ➠ `4`
   - `5` ➠ `0xb1`                |             - `0xb1` ➠ `5` 
   - `6` ➠ `0xbd`                |             - `0xbd` ➠ `6` 
   - `7` ➠ `0xb7`                |             - `0xb7` ➠ `7` 
   - `8` ➠ `0xe8`                |             - `0xe8` ➠ `8`
   - `9` ➠ `0xe3`                |             - `0xe3` ➠ `9`



'**정적 분석(Static Analysis)**'은 프로그램을 실행하지 않고 내부 구조나 코드를 분석하는 방식

동적 분석이 실행하면서 관찰하는 방식이라면,  
정적 분석은 실행하지 않고 프로그램 내부를 살펴보는 방식




둘 중 하나만 사용하는 것이 아니라,  
상황에 따라 두 방법을 함께 사용하는 것이 중요함


  



'**Ghidra**'는 리버스 엔지니어링에 사용하는 분석 도구


 `test-program` 혹은 Linux 터미널에서 아래 명령어를 수행하여 설치

&lt;파일 다운로드&gt;

```bash
wget "https://dreamhack-lecture.s3.amazonaws.com/uploads/reversing/intro/test-program"
```

이 파일은 Linux 실행 파일이므로 Ghidra에 불러와 분석할 수 있음!



Ghidra를 실행하면 먼저 프로젝트를 생성해야 함

&lt;프로젝트 생성 흐름&gt;

 `File` 선택  
 ➠ `New Project` 선택 
 ➠ `Non-Shared Project` 선택 
 ➠ 프로젝트 위치 지정 
 ➠ 프로젝트 이름 입력 
 ➠ `Finish` 선택

이번 예시에서는 프로젝트 이름을 `dreamhack`으로 설정함

`Non-Shared Project`는 혼자 사용하는 일반 프로젝트라고 보면 됨

프로젝트가 생성되면  
Ghidra 화면에 프로젝트 공간이 만들어짐


하지만 이 코드는 원래 소스 코드와 완전히 같지는 않음

&lt;주의할 점&gt;

- 변수명이 원래 이름으로 복원되지 않을 수 있음
- 함수명이 자동 생성된 형태로 보일 수 있음
- 컴파일 과정에서 바뀐 구조가 반영될 수 있음
- 사람이 이해하기 쉽게 재구성한 결과일 뿐임



**`main`** 함수는 프로그램이 시작되는 중요한 함수

디컴파일 결과에서 `main`을 보면  
프로그램이 어떤 입력을 받고, 어떤 조건에 따라 동작하는지 확인할 수 있음


정적 분석에서는 이런 함수들을 기준으로  
프로그램의 전체 흐름을 파악할 수 있음


프로그램 안에는 `main` 함수 외에도 다른 함수들이 존재할 수 있음

`add(local_lc, local_18)` 에서 `add`를 더블 클릭하면 그 함수의 코드 확인 가능 


&lt;예시&gt;

```c
int add(int param_1, int param_2)
{
    return param_2 + param_1;
}
```

이 코드를 보면 `add` 함수는 두 값을 더해서 반환하는 함수로 볼 수 있음

여기서 `param_1`, `param_2`도 원래 변수명이 아니라  
Ghidra가 자동으로 붙인 이름일 수 있음

즉, 정적 분석에서는 함수 하나하나를 확인하면서  
각 함수가 어떤 역할을 하는지 추측해야 함


But, 디컴파일러가 있다고 해서 프로그램을 완벽히 이해할 수 있는 것은 아님

디컴파일러는 기계어를 사람이 읽기 쉬운 형태로 바꿔줄 뿐,  
프로그램의 의미를 완전히 설명해주지는 않음

&lt;디컴파일 결과를 볼 때 주의할 점&gt;

- 원래 소스 코드와 다를 수 있음
- 변수명과 함수명이 사라져 있을 수 있음
- 최적화 때문에 코드 구조가 달라질 수 있음
- 분석자가 직접 의미를 해석해야 함

∴ 디컴파일러는 정적 분석을 돕는 도구이지, 분석을 대신해주는 도구는 아님
