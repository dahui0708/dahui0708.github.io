# Dreamhack Dream Beginners 내용 정리


## '해킹'이란?

타인의 컴퓨터 시스템에 무단으로 침입해서 정보 또는 권한을 탈취하거나, 시스템을 파괴하는 것.
즉, 취약한 부분을 찾아내고 이를 공격하는 과정


## 해킹 주요 분야

해킹 주요 분야는 3 가지 분야로 나눔.

- Web Hacking(웹 해킹): 웹 서비스를 대상으로 하는 분야
- System Hacking / Pwnable(시스템 해킹): 프로그램이나 시스템의 취약점을 분석하는 분야
- Reverse Engineering(리버스 엔지니어린(=리버싱)): 프로그램을 거꾸로 분석해서 동작 원리를 보는 분


## '코딩'이란?

프로그래밍 언어를 사용하여 컴퓨터에서 명령할 수 있는 체계를 생성하는 행위로, 
특정 프로그래밍 언어로 컴퓨터에게 동작을 지시할 수 있음.
(드림핵에서는 C언어와 Python을 먼저 읽히는 것을 권장!)


## 컴퓨터 과학 

컴퓨터를 이용한 모든 작업과 그 기반 이론을 연구하는 학문으로,
코딩뿐만 아니라 계산 이론, 알고리즘, 소프트웨어 설계, 네트워크 등 광범위한 영역을 포함.

이러한 컴퓨터 과학 지식을 응용하여 프로그램이나 시스템의 취약점을 발견하고 공격 행위를 해킹이라고함.
But, 컴퓨터 과학을 깊게 알아야만 해킹을 배울 수 있는 건 아님.

보안 공부를 하려면 컴퓨터가 데이터를 어떻게 표현하는지 알아야 하는데 여기서는 진법, 비트, 바이트, 바이트 오더링, 비트 연산을 먼저 다룸.


### 진법

한 자릿수에 표현할 수 있는 숫자의 개수
즉, 수를 표현하는 방식
n진수: n진법으로 나차낸 수

- 2진법: 0과 1로 표현으로 0과 1의 조합을 비트(bit)
- 10진법: 사람이 일반적으로 쓰는 숫자(0~9) 표현
- 16진법: 0~9, A~F를 사용해서 표현(보통 Ox라는 접두어를 붙임)


### 비트와 바이트

bit는 컴퓨터가 데이터를 표현하는 가장 작은 단위  
byte는 8개의 bit로 구성된 단위

- 1byte = 8bit
- bit는 0 또는 1로 표현
- byte 단위는 파일 크기, 메모리, 데이터 표현에서 자주 사용
- 부호 비트: MSB가 0이면 양수, 1이면 음

이 부분은 단순 단위처럼 보이지만  
나중에 메모리 구조나 시스템 해킹에서 계속 연결될 것 같음


### 바이트 오더링

2byte 이상의 테이터를 메모리에 연속적으로 저장할 때 각 바이트가 메모리에 정렬되는 방식

- Big Endian: 큰 바이트부터 메모리의 작은 주소에 저장
- Little Endian: 작은 바이트부터 메모리의 낮은 주소에 저장

여기서 핵심은 “값이 메모리에 저장되는 순서가 방식에 따라 달라진다”는 점!


### 비트 연산

피연산자를 2진수 단위로 표현하여 비트(bit) 단위로 연산하는 것

논리 연산을 수행하거나, 비트를 특정 값만큼 이동하는 시프트(shift)연산을 수행

- 논리 연산: 참(1,true)/거짓(0,false) 기준으로 판단
  => ||(or), &&(and), !(not)
- 비트 연산자: 비트 단위로 연산
  => |(or), &(and), ^(xor), ~(not)
- 시프트 연산자: 비트를 왼쪽이나 오른쪽으로 이동
  => <<, >> (산술 시프트), >>> (논리 시프트)


## 인코딩과 디코딩

인코딩은 데이터를 특정 형식으로 변환하는 것
디코딩은  변환된 데이터를 원래 값으로 복원하는 것

즉, 데이터를 다른 형식으로 바꾸거나 다시 원래 형태로 되돌리는 과정

- ASCII: 문자를 숫자로 표현하는 방식  
- Unicode: 여러 나라 문자를 표현하기 위한 표준  
- URL Encoding: URL에서 사용할 수 없는 문자를 변환하는 방식  
- Base64: 데이터를 문자 형태로 바꿔서 표현하는 방식



## 운영체제(os)

프로그램 실행과 시스템 자원 관리를 담당하는 것

- 커널(Kernel): 운영체제의 핵심 부분, 하드웨어 관리
- 셀(Shell): 사용자가 명령어를 입력해 운영체제와 상호작용하는 부분

가상머신은 실습 환경을 따로 만들 수 있다는 점이 중요  
실습하다가 문제가 생겨도 실제 PC 환경과 분리할 수 있음!


## 가상 머신(vm)

하나의 컴퓨터 안에서 다른 운영체제 환경을 실행하는 기술

장점: 하나의 운영체제 위에 다양한 운영체제 환경을 구축할 수 있음


## 리눅스 기본 명령어

리눅스 명령어는 앞으로 실습할 때 계속 사용될 기본 도구

처음부터 전부 외우기보다는  
현재 위치 확인, 이동, 파일 확인, 생성, 삭제 흐름으로 이해하는 게 나을 것 같음.

자주 쓴 명령어

- `id`: 현재 유저 ID와 그룹 ID 확인
- `pwd`: 현재 위치 확인
- `ls`: 디렉토리 내용 확인
- `cd`: 디렉토리 이동
- `mkdir`: 디렉토리 생성
- `touch`: 빈 파일 생성
- `mv`: 파일 이동 또는 이름 변경
- `rm`: 파일 또는 디렉토리 삭제
- `cat`: 파일 내용 출력
- `file`: 파일 유형 확인
- `echo`: 문자열 출력 또는 파일에 저장
- `cp`: 파일 또는 디렉토리 복사
- `grep`: 특정 문자열 검색
- `man`: 명령어 매뉴얼 확인
- `curl`: 서버와 데이터 송수신

명령어는 설명만 보면 잘 안 익숙해짐  
직접 터미널에 입력하면서 익히는 게 필요!

## 경로

리눅스에서 파일 위치를 나타내는 방식

절대 경로는 `/` 루트 디렉토리부터 전체 위치를 적는 방식  
상대 경로는 현재 위치를 기준으로 이동 경로를 적는 방식

- `/`로 시작하면 절대 경로
- 현재 위치 기준이면 상대 경로
- `..`은 상위 디렉토리로 이동
  
`pwd`로 현재 위치를 확인하면서 보면 이해하기 쉬움!


## 와일드카드

리눅스에서 파일명이나 문자열을 찾을 때 사용하는 특수 문자

- `?`: 임의의 문자 1개
- `*`: 임의의 문자 0개 이상
- `[ ]`: 지정한 범위 안의 문자

파일이 많을 때 특정 패턴에 맞는 파일을 찾는 데 사용 가능!


## 리다이렉션과 파이프

리다이렉션은 입력이나 출력을 다른 곳으로 바꾸는 개념  
파이프는 앞 명령어의 결과를 뒤 명령어의 입력으로 넘기는 개념

명령어 실행 결과를 화면에만 출력하지 않고  
다른 파일로 보내거나 다른 명령어와 연결할 수 있음
 

## 리눅스 권한

파일이나 디렉토리에 누가 접근할 수 있는지 정하는 개념

- 유저(user): 파일 소유자
- 그룹(group): 소유자가 속한 그룹
- other: 그 외 사용자

관련해서 알아둘 것

- UID: 사용자를 구분하는 ID
- GID: 그룹을 구분하는 ID
- `/etc/passwd`: 유저 정보 저장
- `/etc/group`: 그룹 정보 저장

사용자가 파일에 접근하면 리눅스가 UID와 GID를 확인해서 권한 판단


## 파일 및 디렉토리 권한

권한은 읽기, 쓰기, 실행으로 구분함

- `r`: 읽기(Read)
- `w`: 쓰기(Write)
- `x`: 실행(Execute)
- `-/`: 권한 없음

권한은 `ls -l` 명령어로 확인 가능


## 리눅스 디렉토리 구조

리눅스의 최상위 디렉토리는 `/`

이를 루트 디렉토리라고 하며, 모든 파일과 디렉토리는 루트 디렉토리 아래에 존재함

루트 디렉토리 확인 명령어

```bash
cd /
ls -l /
```

`ls -l /`을 실행하면 루트 디렉토리 안에 있는 주요 디렉토리를 확인할 수 있음

자주 봐야 할 디렉토리

- `/bin`: 기본 명령어나 프로그램이 들어있는 디렉토리
- `/boot`: 시스템 부팅에 필요한 파일 저장
- `/dev`: 장치 파일 저장
- `/etc`: 운영체제와 서비스 설정 파일 저장
- `/home`: 일반 사용자의 홈 디렉토리
- `/lib`: 프로그램 실행에 필요한 라이브러리 저장
- `/opt`: 추가 소프트웨어 패키지 저장
- `/proc`: 커널과 프로세스 정보를 파일 형태로 제공
- `/root`: root 사용자의 홈 디렉토리
- `/sbin`: 시스템 관리용 명령어 저장
- `/tmp`: 임시 파일 저장
- `/usr`: 사용자 프로그램, 문서, 라이브러리 저장
- `/var`: 로그처럼 자주 변경되는 파일 저장

처음부터 모든 디렉토리를 외울 필요는 없어 보임

우선 자주 볼 것 같은 디렉토리

- `/home`
- `/etc`
- `/bin`
- `/tmp`
- `/var`

특히 `/etc`는 설정 파일, `/var`는 로그 파일과 연결해서 기억하면 좋을 것 같음


## Web Hacking(웹 해킹)

웹 해킹은 웹 서비스에서 발생할 수 있는 취약점을 이해하고 분석하는 분야

웹 서비스는 단순히 화면만 있는 것이 아니라 브라우저, 서버, 데이터베이스가 요청과 응답을 주고받으면서 동작함

웹 서비스에서 자주 등장하는 기능

- 로그인
- 게시판
- 검색
- 결제
- 파일 업로드
- 사용자 입력 처리

이런 기능들은 사용자의 입력을 받고, 서버에서 처리한 뒤, 데이터베이스와 연결되는 경우가 많음

기능이 많고 구조가 복잡할수록 의도하지 않은 동작이나 취약점이 생길 수 있음



## Web Hacking 학습 전에 필요한 것

웹 개발을 전문 개발자 수준으로 깊게 알아야 하는 것은 아님  
웹 서비스의 구조를 읽고, 코드가 어떤 흐름으로 동작하는지 파악할 수 있는 정도가 먼저 필요함

강의에서 말한 기준

- Flask, NodeJS, Spring 중 하나로 작성된 웹 소스 코드를 읽을 수 있는 정도
- 브라우저와 서버가 어떻게 통신하는지 이해
- 요청과 응답 흐름 이해
- 데이터베이스와 웹 애플리케이션 연결 구조 이해

웹 해킹에서 중요하게 봐야 할 부분

- HTTP와 HTTPS
- HTTP 상태 코드
- GET / POST 메소드 차이
- 로그인 상태 유지 방식
- 사용자 입력값 검증
- 클라이언트와 서버의 역할 차이
- 데이터베이스와 SQL 쿼리 흐름

웹 서비스가 정상적으로 어떻게 동작하는지 먼저 알아야 취약한 부분도 찾을 수 있을 것 같음


## Reverse Engineering(리버스 엔지니어링)

리버스 엔지니어링은 프로그램을 역으로 분석해서 내부 동작 원리를 파악하는 분야

줄여서 Reversing(리버싱)이라고도 부름

일반적인 개발이 소스 코드를 작성하고 컴파일해서 실행 파일을 만드는 과정이라면,  
리버싱은 반대로 실행 파일이나 바이너리를 보고 프로그램이 어떻게 동작하는지 분석하는 과정

리버싱에서 자주 나오는 개념

- Binary: 컴파일된 실행 파일 또는 이진 데이터
- Disassembler: 기계어를 어셈블리 코드로 바꿔주는 도구
- Decompiler: 실행 파일을 사람이 읽기 쉬운 코드 형태로 복원해주는 도구

리버싱은 소스 코드가 없어도 프로그램의 동작을 추측할 수 있다는 점이 중요함

단순히 사람이 읽을 수 있는 코드인지 아닌지만으로 리버싱 여부가 결정되는 것은 아님  
핵심은 프로그램의 동작 원리를 분석하는 과정에 있음


## Reverse Engineering 학습 전에 필요한 것

리버싱을 공부하려면 프로그램이 어떤 방식으로 실행되는지 이해할 필요가 있음

먼저 알아두면 좋은 것

- C 언어 코드 흐름 이해
- 컴파일 과정 이해
- 어셈블리 코드 기초
- 메모리와 레지스터 개념
- 스택 프레임 구조
- 프로그램 실행 흐름 분석

특히 C 언어와 어셈블리를 어느 정도 읽을 수 있으면 리버싱을 따라가기 쉬워짐


## System Hacking(시스템 해킹)

시스템 해킹은 프로그램이나 시스템의 취약점을 분석하는 분야

주로 C 언어 기반 프로그램, 메모리 구조, 운영체제 동작 방식과 관련이 많음

시스템 해킹에서 중요한 점은 프로그램이 시스템 상에서 어떻게 실행되는지 이해하는 것

강의에서 나온 주요 키워드

- Pwnable
- Remote Code Execution
- Stack Buffer Overflow
- 메모리 구조
- 함수 호출
- 스택 프레임
- 32bit / 64bit 환경 차이

C 언어와 리버싱 기초를 먼저 잡고 들어가면 이해하는 데 도움이 될 것 같음


## System Hacking 학습 전에 필요한 것

시스템 해킹을 공부하기 전에는 C 언어가 컴파일된 뒤 어떻게 동작하는지 이해해야 함

중요하게 봐야 할 부분

- C 언어 코드 실행 흐름
- 함수 호출 규약
- 스택 프레임 구조
- 레지스터 역할
- 메모리 구조
- 32bit와 64bit 차이
- 어셈블리 코드 해석

특히 스택 버퍼 오버플로우 같은 취약점을 이해하려면  
스택이 어떻게 사용되는지, 함수가 호출될 때 메모리가 어떻게 변하는지 알아야 함


## Cryptography(암호학)

암호학은 정보를 안전하게 보호하고 통신하기 위한 방법을 다루는 분야

평문을 암호문으로 바꾸거나, 암호문을 다시 평문으로 복원하는 과정에서 여러 알고리즘과 연산이 사용됨

구분해야 할 개념

- Plaintext: 암호화되기 전 원래 데이터
- Ciphertext: 암호화된 데이터
- Key: 암호화와 복호화에 사용되는 값
- Encryption: 평문을 암호문으로 바꾸는 과정
- Decryption: 암호문을 평문으로 되돌리는 과정

암호학은 개인정보 보호, 전자상거래, 클라우드 서비스, 인증 시스템 등에서 사용됨


## Cryptography 학습 전에 필요한 것

암호학을 공부하기 전에 비트 연산, 모듈로 연산, Python에 익숙해지면 좋음

중요하게 봐야 할 부분

- AND, OR, XOR, NOT 같은 비트 연산
- SHIFT 연산
- 모듈로 연산
- 나머지 계산
- 거듭제곱 계산
- Python 코드 흐름 읽기

비트 연산은 여러 암호 알고리즘의 기초가 됨

모듈로 연산은 나머지 연산이라고 생각하면 되고,  
암호학에서는 큰 수를 다룰 때 자주 사용되는 개념으로 보임

Python은 암호 알고리즘을 실습하거나 워게임 문제를 풀 때 자주 사용됨  
따라서 Python 코드를 읽고 간단히 수정할 수 있는 정도는 필요해 보임


## Digital Forensics(디지털 포렌식)

디지털 포렌식은 디지털 장치에 남아 있는 데이터를 수집, 분석, 보존하는 분야

컴퓨터나 저장장치에 남은 흔적을 분석해서 사건의 흐름을 파악하는 데 사용됨

디지털 포렌식에서 다루는 내용

- 삭제된 파일 복구
- 로그 분석
- 파일 시스템 분석
- 메모리 분석
- 네트워크 패킷 분석
- 악성코드 분석

단순히 삭제된 파일을 복구하는 것만이 아니라,  
시스템에 남은 여러 흔적을 통해 어떤 일이 있었는지 분석하는 과정이 중요함

사이버 범죄 수사, 침해 사고 대응, 내부 정보 유출 조사 같은 분야와 연결됨


## Digital Forensics 학습 전에 필요한 것

디지털 포렌식은 처음부터 깊은 배경지식이 없어도 따라갈 수 있는 분야로 보임

- CLI 환경 사용 경험
- 파일 이름과 확장자 개념
- 삭제된 파일 복구에 대한 관심
- 로그 파일 이해
- 해시 개념
- 암호화와 복호화 개념
- 타임스탬프 개념
- 실행 파일 구조
- 가상머신 사용 경험

특히 로그, 파일 시스템, 타임스탬프는 포렌식에서 자주 연결될 것 같음


## Netcat(nc)

Netcat은 네트워크를 통해 서버와 데이터를 주고받을 때 사용하는 도구

보안 실습이나 워게임에서는 특정 서버의 Host와 Port로 접속해야 하는 경우가 많음  
이때 `nc` 명령어를 사용해서 서버와 직접 통신할 수 있음

기억할 것

- `nc`는 Netcat 명령어
- 서버와 클라이언트가 TCP 통신할 때 사용 가능
- 웹 브라우저가 아니라 터미널에서 직접 접속하는 방식
- Dreamhack 워게임에서 자주 사용됨

Netcat 설치

```bash
sudo apt update && sudo apt install netcat
```

기본 사용 형식

```bash
nc Host Port
```

- `Host`: 접속할 서버 주소
- `Port`: 서버에서 열어둔 통신 번호

브라우저로 접속하는 방식과 다르게  
터미널에서 직접 입력을 보내고 서버의 응답을 확인하는 것이 핵심


## nc 사용법

`nc` 명령어는 Host와 Port를 지정해서 사용함

가장 기본적인 형태

```bash
nc hostname port
```

예시

```bash
nc google.com 80
```

80번 포트는 HTTP 통신에서 자주 사용되는 기본 포트

연결 후 아래처럼 HTTP 요청을 직접 입력할 수 있음

```text
GET / HTTP/1.1
```

이렇게 입력하면 서버에서 응답을 보내는 것을 확인할 수 있음

여기서 알 수 있는 것

- 브라우저가 대신 보내던 요청을 직접 입력해볼 수 있음
- 서버가 어떤 응답을 보내는지 터미널에서 확인 가능
- 네트워크 통신은 요청과 응답 구조로 동작함

즉, `nc`는 단순 접속 명령어가 아니라  
서버와 직접 통신해보는 도구에 가까움

이 문제는 웹 브라우저로 접속해서 푸는 문제가 아니라  
`nc` 명령어로 서버에 접속해서 푸는 문제

문제 페이지에서 먼저 확인할 것

- 문제 설명
- 접속 정보
- Host
- Port
- 문제 파일
- Flag 제출 위치

문제 설명에는 풀이에 필요한 조건이나 힌트가 들어 있을 수 있음  
문제마다 제공되는 정보가 다를 수 있으므로 먼저 Description을 확인하는 것이 중요


## 접속 정보 확인

Dreamhack 워게임은 보통 VM을 통해 문제 환경에 접속함

접속 흐름

1. 문제 페이지에서 서버 생성하기 버튼 클릭
2. VM 접속 정보 생성 확인
3. Host와 Port 확인
4. 문제 유형에 맞는 방식으로 접속

접속 방식은 크게 두 가지로 구분 가능

- 웹 문제: `http://Host:Port` 형식으로 브라우저에서 접속
- 시스템/포너블 문제: `nc Host Port` 형식으로 터미널에서 접속

이번 `Welcome-Beginners` 문제는 `nc`로 접속하는 방식

예시 형식

```bash
nc host3.dreamhack.games 14309
```

실제 Host와 Port는 서버를 생성할 때마다 달라질 수 있음  
따라서 문제 페이지에 표시된 값을 그대로 사용해야 함


## nc로 문제 서버 접속

터미널에서 문제 페이지에 나온 Host와 Port를 입력하면 서버에 접속됨

```bash
nc Host Port
```

서버에 접속하면 입력을 요구하는 문장이 출력됨

이번 문제에서는 `"Dreamhack"`을 입력하면 flag가 출력되는 구조

실습 흐름

1. `nc Host Port` 입력
2. 서버 접속
3. `Enter "Dreamhack"` 문구 확인
4. `Dreamhack` 입력
5. flag 출력 확인

이 실습의 핵심은 서버에 직접 접속해서 값을 입력하고,  
서버가 돌려주는 응답을 확인하는 과정


## 문제 파일 확인

문제 페이지에서 문제 파일을 다운로드할 수 있음

압축을 해제하면 문제를 푸는 데 필요한 파일이 들어 있음  
이번 문제에서는 `chall.c` 파일을 확인할 수 있음

소스 코드에서 확인할 흐름

- flag 파일 열기
- flag 내용 읽기
- 사용자 입력 받기
- 입력값과 `"Dreamhack"` 문자열 비교
- 조건이 맞으면 flag 출력

핵심 코드

```c
char cmp_str[10] = "Dreamhack";
char inp_str[10];

printf("Enter \"Dreamhack\" : ");
scanf("%9s", inp_str);

if(strcmp(cmp_str, inp_str) == 0){
    puts("Welcome Beginners!");
    puts(flag);
}
```

여기서 중요한 부분은 `strcmp`

`strcmp`는 두 문자열을 비교하는 함수

- `cmp_str`: 비교 기준 문자열
- `inp_str`: 사용자가 입력한 문자열

`cmp_str`에는 `"Dreamhack"`이 들어 있음  
따라서 사용자가 `Dreamhack`을 입력하면 조건이 참이 되고 flag가 출력됨

소스 코드가 제공되는 문제는  
무작정 실행하기보다 입력값이 어디에 저장되고, 어떤 조건을 만족해야 하는지 먼저 확인하는 것이 중요


## Flag 제출

출력된 flag는 문제 페이지의 Flag 입력 칸에 제출함

Dreamhack 공식 워게임의 flag 형식은 보통 아래와 같음

```text
DH{...}
```

제출할 때는 `DH{}`까지 포함해서 전체를 입력해야 함

정리할 것

- `nc`는 Host와 Port로 서버에 직접 접속하는 명령어
- 웹 문제와 nc 접속 문제는 접속 방식이 다름
- 문제 페이지에서 Host, Port를 먼저 확인해야 함
- 소스 코드가 있으면 입력값 비교 흐름을 확인해야 함
- 이번 문제는 `Dreamhack`을 입력하면 flag가 출력되는 구조


## SSH

SSH는 원격 Linux 서버에 안전하게 접속할 때 사용하는 방식

SSH는 Secure Shell의 줄임말로, 원격 서버와 클라이언트가 암호화된 통신을 할 수 있게 해주는 프로토콜

워게임이나 CTF 문제에서는 문제 서버에 직접 접속해야 하는 경우가 있음  
이때 `ssh` 명령어를 사용해서 원격 서버의 터미널에 접속 가능

기억할 것

- SSH는 원격 서버에 접속할 때 사용
- 통신 과정이 암호화됨
- 서버에 접속한 뒤 명령어를 직접 실행할 수 있음
- Linux 서버 문제나 시스템 실습에서 자주 사용됨

Netcat이 서버와 간단히 데이터를 주고받는 느낌이라면  
SSH는 원격 서버 안에 직접 로그인해서 터미널을 사용하는 방식에 가까움


## SSH 명령어 준비

Linux와 macOS에서는 터미널에서 기본적으로 `ssh` 명령어를 사용할 수 있음

Windows에서는 OpenSSH 클라이언트가 필요할 수 있음

Windows에서 확인할 부분

- 설정
- 앱
- 선택적 기능
- OpenSSH 클라이언트 설치 여부 확인

터미널에서 아래 명령어를 입력했을 때 사용법이 출력되면 준비된 상태

```bash
ssh
```

명령어가 정상적으로 인식되면 SSH 접속 준비 완료


## SSH 사용법

SSH 기본 형식

```bash
ssh user@HOST -p PORT
```

구분해야 할 것

- `user`: 원격 서버에 존재하는 사용자 이름
- `HOST`: 접속할 서버 주소 또는 도메인
- `PORT`: 접속할 포트 번호
- `-p`: 포트 번호를 지정할 때 사용하는 옵션

예시 형식

```bash
ssh user@host3.dreamhack.games -p 11051
```

여기서 Host와 Port는 문제 서버를 생성할 때마다 달라질 수 있음  
따라서 문제 페이지의 접속 정보를 그대로 확인해야 함


## SSH 인증 방식

SSH 접속할 때 사용자를 인증하는 방식은 크게 두 가지

첫 번째는 패스워드 방식

```bash
ssh user@HOST -p PORT
```

명령어를 입력한 뒤 서버가 패스워드를 요구하면  
주어진 패스워드를 입력해서 접속하는 방식

두 번째는 개인 키 파일을 사용하는 방식

```bash
ssh user@HOST -p PORT -i 개인키파일경로
```

`-i` 옵션은 개인 키 파일을 지정할 때 사용함

패스워드 방식은 간단하지만, 패스워드가 약하면 위험할 수 있음  
개인 키 방식은 키 파일을 이용해서 사용자를 확인하는 방식

이번 강의에서는 SSH 접속 방법 자체를 익히는 것이 목적이라  
인증 구조를 깊게 다루지는 않음


## SSH 접속 예시

문제 페이지에서 접속 정보를 확인함

확인해야 할 정보

- Host
- Port
- ID
- Password 또는 개인 키 파일

패스워드로 접속하는 경우

```bash
ssh bguser@host3.dreamhack.games -p 11051
```

명령어 실행 후 패스워드를 입력하면 서버에 접속할 수 있음

개인 키로 접속하는 경우

```bash
ssh bguser@host3.dreamhack.games -p 11051 -i 개인키파일경로
```

같은 서버라도 문제에서 제공하는 인증 방식에 따라  
패스워드를 입력할 수도 있고 개인 키 파일을 사용할 수도 있음

중요한 점

- `user@HOST` 형식으로 작성
- 포트 번호가 있으면 `-p` 옵션 사용
- 개인 키 파일이 있으면 `-i` 옵션 사용
- Host와 Port는 문제 페이지에서 확인


## 실습: SSH

Dreamhack의 SSH 실습 문제는 원격 서버에 접속해서 flag 파일을 읽는 것이 목표

문제에서 제공되는 정보

- ID
- Password
- Host
- Port

접속 흐름

1. 문제 페이지에서 서버 생성
2. Host와 Port 확인
3. ID와 Password 확인
4. 터미널에서 SSH 명령어 입력
5. 서버 접속 후 파일 목록 확인
6. flag 파일 읽기

접속 명령어 형식

```bash
ssh ID@HOST -p PORT
```

접속하면 처음에는 서버 신뢰 여부를 묻는 메시지가 나올 수 있음  
계속 접속하려면 `yes`를 입력함

그다음 패스워드를 입력하면 원격 서버에 로그인됨


## SSH 실습에서 사용한 명령어

서버에 접속한 뒤 현재 디렉토리의 파일을 확인함

```bash
ls
```

파일 목록에서 `flag` 파일이 보이면 내용을 확인함

```bash
cat flag
```

`cat` 명령어는 파일 내용을 터미널에 출력할 때 사용함

이번 실습 흐름은 단순함

- SSH로 서버 접속
- `ls`로 파일 확인
- `cat flag`로 flag 읽기
- 출력된 `DH{...}` 형식의 flag 제출

이번 실습에서 정리할 핵심

- SSH는 원격 서버에 로그인해서 명령어를 실행하는 방식
- `user@HOST` 형식으로 접속함
- 포트 번호는 `-p` 옵션으로 지정함
- 개인 키 파일은 `-i` 옵션으로 지정함
- 서버에 접속한 뒤에는 일반 Linux 명령어를 사용할 수 있음
